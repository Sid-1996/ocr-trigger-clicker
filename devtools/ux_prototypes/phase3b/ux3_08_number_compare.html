問題：數值欄位 setDecimals(15)，Qt 會把小數點後全補滿 → 55.0000000000。 修法只改「顯示字串」（textFromValue），widget 值、存檔值、比較結果都不變。

改善前 已修正

小數點後永遠 10 位，看不出重點；使用者常誤以為要自己算位數。

輸入 55 → 顯示 55；55.5 → 55.5；55.1234 → 55.1234。可自行輸入試試。

§2 數字格式

問題：欄位直接暴露 -?\d+\.?\d*，一般使用者無法判斷要改哪一段。 修法：常用格式用白話選單，正規表示式收進「進階設定」，選「自訂格式」才需要碰。

改善前 已修正

只有一個輸入框。\d、?、* 對一般玩家沒有意義； 打錯也只變紅框，不知道怎麼改。

改善後 現況

從文字中找出第一個數字，整數與小數都支援。
格式不正確：括號或反斜線沒有配對，請檢查後再試。

進階使用者直接寫正規表示式；一般使用者不需要打開這一區。

切換格式時，下方「進階」欄位會同步顯示實際使用的正規表示式（可驗證、可再修改）。

三種常用格式的實際匹配語意
選項使用的正規表示式「Lv.55」「55.5」「-12」「26%」
一般數字（預設）-?\d+\.?\d*5555.5-1226
整數-?\d+5555（只取整數段）-1226
小數-?\d+\.\d+不匹配55.5不匹配不匹配

沒有「百分比」選項：現行語意本來就不把 % 轉成數字（26% 取 26，不會變 0.26）， 加一個只改名字的選項只會讓選單更難懂。

§3 實際操作流程

新增／編輯「數字比對」步驟 → 選比較方式（≥ > = ≠ …）→ 輸入數值（現在顯示 55 而不是 55.0000000000）。
「數字格式」維持預設一般數字即可涵蓋絕大多數情況；需要「只比整數」或「一定要有小數」時再切換。
只有選「自訂格式（進階）」才會打開正規表示式欄位；格式寫錯會在欄位下方直接說明怎麼修，存檔時保留你輸入的內容。

舊規則開啟後：數值與格式都照原樣顯示，不動就不會改寫；按「儲存」也只會寫回原本的字串。

§4 舊規則相容性

情境行為結果
舊規則 pattern = -?\d+\.?\d*選單顯示「一般數字」存檔字串完全相同（未遷移）
舊規則 pattern = \d{2,4}選單顯示「自訂格式」，欄位保留原值不覆寫、不改寫 JSON
舊規則 pattern 含前後空白逐字保留（不再 strip()）匹配行為不變
只開啟編輯器、不儲存不寫入任何格式變更原檔不動
使用者主動切換格式欄位同步換成該選項的表示式，存檔即採用可預期、可見

JSON schema 不變：仍只有 pattern 一個字串欄位，沒有新增欄位或資料遷移。
