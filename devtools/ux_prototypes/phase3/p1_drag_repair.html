UX3-02 Drag Legacy Marker 修復（C-2a-2）

原始問題

舊任務 Drag 終點是像素偏移（dx/dy），載入時 core 標 _migration{kind=drag_endpoint,status=needs_repair}，執行期只認 end_x/end_y 所以必定 drag_end_invalid。修復表單（banner → 重拾終點 → 確認）已存在，但使用者找不到要修哪一條：步驟清單只顯示「拖曳 座標 → (30,20)」（執行期根本不採用），規則列沒有任何標記，載入提示只是短暫 toast。因此「GUI 修復入口」形同不可見。

修改 1：規則清單（規則層標記）
▸ 每日委託 [3步] [拖曳待修復]
▸ 體力型跑馬 [5步]

標籤由 core validate_drag_endpoint() 統計，只要規則內任一 Drag 為 needs_repair 就出現；不需要展開規則。

修改 2：步驟清單（步驟層摘要＋警示色）
1偵測「開始」
2拖曳 座標 → ⚠ 終點是舊格式，需要修復（點開此步驟）
3等 500ms

修改前第 2 步顯示「拖曳 座標 → (30,20)」——數字看起來有效，實際不會被採用。新版／未設定終點的 Drag 現在分別顯示「拖曳 座標 → (55%,66%)」與「終點未設定」，不再出現沒有意義的 (+0,+0)。

修改 3：步驟表單（原有修復流程，維持不變）
⚠ 這條拖曳規則的終點是舊格式，需要修復後才能執行。
舊格式用像素距離（dx/dy），新格式用視窗比例。請重新拾取一次終點，確認後會清除舊標記。

終點（客戶區比例）：未設定　|　舊格式欄位 dx/dy（唯讀）：dx=30 dy=20

狀態：needs_repair（由 validate_drag_endpoint() 判定，GUI 不自行判斷）

任務載入時提示：「2 個拖曳步驟的終點是舊格式，請開啟該步驟修復」（仍為短暫提示，不搶焦點）
資料安全（修改前後一致）
情境dx/dyend_x/end_y_migration
載入舊資料保留不加自動補（core）
只開啟／一般儲存，未修復保留原值（含小數）不加保留
拾取終點但取消確認保留不寫入保留
確認修復 → 儲存移除寫入比例移除
重載檢查—不變不重現（valid）

遇到無效資料（終點非比例、缺一軸）時按鈕維持停用，不動原資料。紅線：不自動清洗假 marker（keep 決策）；判定以 core validate_drag_endpoint 為唯一來源。
