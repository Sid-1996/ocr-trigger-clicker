# 數字加總採獨立 `sum` 步驟：觸發後對當前幀做快照加總

Status: accepted（2026-10-20）

## 問題

使用者需要把畫面某區域的數字（例如獎勵氣泡的 +26 / +9 / +20）相加後即時顯示。既有 `compare` 只能取第一個數字做比較，`detect` 只能命中關鍵字；把加總硬塞進 `compare` 會讓「比較數值」與「顯示總和」兩種語意混在一起，也無法處理多個數字。

## 決策

新增步驟類型 `sum`（數字加總），形狀為 `[detect 或 match_image → sum]`：

- **觸發**：沿用前一個 `detect` / `match_image` 步驟及其預設 `on_fail: stop`；失敗時規則結束，`sum` 不會執行。不新增觸發欄位。
- **計算**：對加總區域當幀可見的整數做快照求和，不累積、不跨幀保留。
- **更新節奏**：沿用全域 `scan_interval_ms`；群組模式 `loop` 持續更新、`once` 只算一次。UI 只提示，不強制改群組模式。
- **解析**：NFKC 正規化；只取整數；逗號視為千位分隔（`1,234`）；`+`/`-` 號忽略；含 ASCII 英文字母、小數點或 `%` 的 token 略過（`2G`、`1.2K`、`26%` 都不算）。
- **無數字 / 空區域**：空區域不 OCR、記一次警告；區域內沒有可加總數字時不顯示、不失敗，且立即淡出該規則既有的浮層（視為前置條件失效）。
- **顯示**：單一置頂、點擊穿透的浮層，置於加總區域上方（空間不足改下方），文字為「合計 N（M 個數字）」。同一總和需連續穩定約 0.35 秒才顯示，避免畫面切換／數字動畫的中途值一閃而過；穩定後每次讀取重置 5 秒淡出計時。
- **淡出**：規則失敗停止、加總區域清空、或該規則不再被評估時，浮層立即淡出，不需等到 5 秒計時。

## 考慮過的選項

- **擴充 `compare`**：少一個步驟類型，但比較與加總語意、參數與輸出都不同，表單會變成兩個功能的混合體
- **累積模式**：可統計一段時間的總量，但需要重置條件與跨幀狀態，普通使用者難以預期；快照模式先用最小語意覆蓋需求
- **獨立 `sum` 步驟（採用）**：重用既有 OCR、ROI、群組與執行日誌，不動主循環節奏；觸發交給既有偵測步驟，責任單一

## 後果

- `core/rule_migration.py:_STEP_DEFAULTS` 新增 `sum`，`task_management` 白名單自動跟隨
- `core/21_number_sum.py` 負責解析與求和（純函式，可單獨自檢）
- `core/05_main_loop.py:_handle_sum` 經 `on_sum` 回呼把區域螢幕座標與結果送到 GUI、`on_sum_hide` 通知淡出；`gui/sum_overlay.py` 只負責顯示與淡出
- 舊任務不含 `sum`，完全向下相容；加總區域為必填，未設定時步驟略過並在執行日誌提示
- 浮層必須落在加總區域之外，避免被下一次截圖／OCR 讀到自己的文字
